## 4. The Fire and Light Pop shader (CnCLightGuard.fx)
- Two techniques, a PAIR like UI Before/After: `LightGuard_Before` (display label "0_ Fire and Light Pop START", no settings, only saves the untouched game frame into `LG_Before`) and `LightGuard_After` ("0_ Fire and Light Pop END", holds ALL settings). Shell noticed two "3_" entries and was unsure; the labels were then renamed to START/END. **He had been moving the first one, which has no sliders, which is why "nothing changed".** Tell him plainly: tweak END.
- v1 (restore fire and lamps to the game's original colours) was the WRONG concept: see section 2. v2 (current) uses the game frame only to FIND fire and small lights and as a brightness floor; the colour is the preset's own grade, pushed hotter/brighter. Fire: blend `Fire_Anchor` of the original hue back in so a cold grade cannot make fire grey, then richer (`Fire_Saturation`), brighter (`Fire_Gain`), and never dimmer than the game's luma. Lights: anchor to original colour, push toward white (`Lamp_Boost`), luma floor. Glow: a small separable Gaussian halo from a "lights and fire" source pass (`Glow_Strength`, `Glow_Size`).
- Detection: lamp = pixel much brighter than a ring of 8 neighbours at `Lamp_Radius` px (default 3) AND luma above about 0.5 to 0.8 AND low saturation. Fire = warm hue (r >= g >= b), and either very bright and saturated (max above 0.92, sat above 0.38) or standing out from its surroundings. `Fire_Reach` widens it. These thresholds are guesses tuned by reasoning, never seen on real frames.
- Sliders and defaults (END): Fire_Strength 1.0, Fire_Gain 0.25, Fire_Saturation 0.3, Fire_Anchor 0.35, Fire_Reach 0.0, Lamp_Strength 1.0, Lamp_Boost 0.4, Lamp_Anchor 0.5, Lamp_Radius 3.0, Glow_Strength 0.7, Glow_Size 1.6, Debug_View 0. **Debug_View**: "Show masks" paints small lights cyan and fire magenta on a darkened frame; "Show saved frame" shows the remembered untouched frame. These are the first thing to use if it looks wrong.
- Every preset has the same `[CnCLightGuard.fx]` block (uniform values as above). Old keys from v1 (Fire_Boost) were removed.
- Compile safety: I built ReShade's own parser from `crosire/reshade` tag `v4.5.4` (`effect_lexer/parser/preprocessor/symbol_table/expression` and the HLSL and GLSL codegens; compile with `g++ -std=c++17 -include cstdint -include cstring -include cstdio -include algorithm -include limits`, driver in `handover/src/fxcheck_main.cpp.txt`). It reproduces the exact warnings in Shell's log for `CnCUIskip.fx`, so it is faithful. Include path needs `ReShade.fxh` and `ReShadeUI.fxh`, which live only on his PC (stage them from `reshade-shaders\Shaders`). Run it on any new shader before committing. (It does not catch D3D fxc warnings.) `lgsim_numpy_sim_of_pop.py.txt` is a numpy port used to sanity-check the pop maths (dulled headlight (140,153,168) to about (251,255,255); cold-graded orange fire (140,84,18) to about (255,138,0)).

## 5. Findings from Shell's tests and from the game folder
- After v1 on Midnight he said it looked "washy again" and lights and explosions were gone. Suspect: v1's fire mask (max above 0.86, sat above 0.28) probably caught bright sand and rock and put ungraded original colour back, undoing the grade. v2 tightened it. Not verified. If Midnight is still washy, first untick START and END to see whether the pair is responsible; if not, the LUT/chain is (the LUT differs from v4 only by a narrow lamp gate, mean change 0.35 of 255).
- ReShade `Performance Mode` was ON in `ReShade.ini`. In that mode there is NO variable editor and uniforms are compile-time constants read from the preset. Shell switched it OFF during testing (`PerformanceMode=0`), so sliders are live now. Keep that in mind: with it on, edit the ini and reload.
- ReShade.ini `CurrentPresetPath` follows whatever preset he last used. `KeyReload` is Ctrl+R. Screenshots (PrtScn, ReShade) never produced files; the game minimises when he tries to capture. Computer-use screenshots were offered but not turned on. That would give real ground truth: ask him to start a skirmish and leave it running, then request access.
- **Why lights pop at night in the game**: the engine darkens the map itself (`INI\night.ini`, `dusk.ini`, `morning.ini`, `day.ini` are map trigger scripts that ramp the map lighting over 1800 frames; `ion.ini` sets ion storm lighting Red 1.62, Green 1.25, Blue 0.34, Ambient 0.5, lightning frequency 10, randomness 90, damage 200). Lights, fire and explosions are drawn self-lit, so they stay bright while everything else drops: pure contrast. On a DAY map, a ReShade night preset darkens lights along with everything, so no contrast. On a NIGHT map, a night preset double-darkens. So presets should be paired with the map's own lighting (day presets for day maps, night presets for night maps), and a ReShade night preset should darken the world but leave bright pixels alone. Shell noticed this himself: in a night skirmish all small lights popped perfectly. This feeds directly into the time-of-day family.
- Night preset: white lights from towers looked blue. The original Night LUT maps pure white to (176,176,178), a 31% dulling, and warm white (255,242,204) to (169,164,154). The blue cause is not established (game night tint versus preset bloom). Cheap test: END > Debug view > "Show saved frame": if the lights are already blue there, it is the game; if white, it is the preset. `Lamp_Boost` pushes lights whiter.
- Old open question: which small lights are missing and what colour. Still unknown; Debug view "Show masks" tells whether they are detected at all.

## 8. Tooling reference
- Build scripts in `handover/src/`: `build2.py.txt` (toolkit: parse_defaults, emit, make_lut, rgb2hsv, hue_mask; its head is exec'd by later builds), `build7_midnight.py.txt` (v3), `build8_midnight_v4.py.txt`, `build9_midnight_v5_REJECTED.py.txt`, `build10_lut_fire_lamp_protect.py.txt`, `build11_preset_chain_guard.py.txt`, `lgsim_numpy_sim_of_pop.py.txt`, `fxcheck_main.cpp.txt`, `CnCLightGuard.fx.txt`. They expect staged files under `/mnt/user-data/uploads/reshade-shaders/` (Custom, Textures, Shaders) and write to `/mnt/user-data/outputs/batchN/`. LUT layout: 1024x32 PNG, x = blue tile*32 + red, y = green.
- Device: `device_stage_files` (PC to `/mnt/user-data/uploads/...`), `device_commit_files` (from `/mnt/user-data/outputs/...`; list every file), `device_list_dir`. No device shell, no delete. Screenshot tools need computer use turned on and approved.
- Note: `build11` still contains the v1 `[CnCLightGuard.fx]` block. The v2 block (keys in section 4) was applied afterwards by an inline replace over the re-staged presets; reuse the v2 keys, not build11's.
- Preset .ini format: `Techniques=` (enabled chain), `TechniqueSorting=` (full menu and execution order), `PreprocessorDefinitions=fLUT_TextureName="..."`, per-effect `[File.fx]` blocks. Unknown keys are ignored. `Isolate_UI=1` in `[CnCUIskip.fx]` protects the 168px right sidebar (22px top strip). Vignette centre 0.395,0.518333. Files use CRLF.
- Levels Plus: InputBlackPoint crushes that channel; a lower InputWhitePoint amplifies it. LUT design: protect bright warm hues and near-white by blending toward identity; tiberium greens (hue about 125) and blues (about 195) keep their Night look.
- Shader compile bug to remember: a technique with a second annotation list inside `#if __RESHADE__ >= 40000` (only CinematicDOF.fx; fixed).
